# 00 — Product Charter

## Product identity

Bauman is designed to become a **Professional Learning Operating System**, not merely a course website, document library, dashboard, LMS, or AI chat wrapper.

Its long-term job is to connect:

`knowledge → learning → practice → assessment → evidence → competency → real output`

while remaining extensible enough that new subjects and resources can be added without routinely modifying Core.

## Primary users

- Learner: studies, practices, produces evidence and artifacts.
- Teacher/content author: builds and reviews learning experiences.
- Reviewer: reviews academic/content evidence within assigned authority.
- Publisher/owner: controls publication and protected administrative decisions.
- Administrator/device manager: manages operational access without becoming academic authority.
- Extension author: adds resource/activity capability through stable contracts rather than Core mutation.

## Product promises

1. **Learning truthfulness** — activity is not mastery.
2. **Core stability** — new content should enter through data, adapters, capabilities, or extensions.
3. **Traceability** — important content, evidence, artifacts and decisions retain provenance/version lineage.
4. **Professional UX** — learners should understand where they are, what matters now and what to do next.
5. **Fail-closed protection** — protected data and administrative authority do not fail open.
6. **Offline-aware operation** — packaged learning remains an architectural concern, not an afterthought.
7. **Long-term compatibility** — valid published content should survive platform evolution through versioned contracts/adapters.

## Explicit non-goals

Bauman must not become:

- a dumping ground for every useful link or PDF;
- a monolithic subject-specific application;
- a system where each subject invents its own identity, storage and UI conventions;
- a platform where AI silently becomes official academic authority;
- a dashboard where completion bars imply competence;
- a production system that mutates live state without exact-revision release evidence.

## Protected current-main truths

The new program inherits, rather than replaces, the current production baseline:

- canonical domain identity and additive migration principles;
- content registry/provenance principles;
- learner-first subject runtimes;
- Device Gate/server-side protected learning boundaries;
- Content Review metadata-only ownership;
- Deep Study Journal reflection-only/non-authoritative boundary;
- academic report truthfulness;
- exact-preview-first production promotion;
- Application Management ownership of the shared live control secret;
- no destructive migration and no implicit production publish.

## Success after 5–10 years

Bauman is successful if adding a new subject or learning package increasingly means:

`import → map → validate → preview → publish`

rather than:

`edit Core → copy UI → patch CSS → add one-off storage → retest everything`.
