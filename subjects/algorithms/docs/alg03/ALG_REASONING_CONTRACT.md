# ALG03 REASONING CONTRACT

## Canonical learning loop
`Problem → Representation → Constraints → Strategy → State/Steps → Invariant → Correctness → Complexity → Implementation → Testing → Trade-off → Transfer`

A final output match is not full evidence. The learner is assessed separately on representation, strategy, trace, invariant, correctness, complexity, implementation, testing, trade-off and explanation.

## Problem decomposition
A task exposes or requires recovery of: input, output, constraints, input-size measure, representation, required operation, performance/memory target, ordering/stability/mutation requirements and relevant canonical IDs. The grader must not invent an unstated requirement.

## Trace evidence
Trace meaningful algorithm state, not bytecode. Canonical examples include binary-search interval state; BFS queue/visited/distance/parent; DFS stack/call path; sorting active indices/comparisons/writes; tree traversal enter/emit/leave events. If neighbor/child order is unspecified, multiple equivalent traces are valid.

## Evidence levels
- L0 Observe — recognition only.
- L1 Execute/Trace — correct operation sequence/state.
- L2 Explain — representation, strategy and preconditions.
- L3 Justify — correctness and complexity using invariant/assumptions.
- L4 Transfer — solve a structurally similar changed-surface task.

## Anti-memorization
Vary labels, values, graph shape, tie conditions and output presentation while preserving target competency.

## Hint ladder
H0 none; H1 restate constraint; H2 representation question; H3 strategy family; H4 invariant/state; H5 one next step; H6 full worked solution only when reveal policy permits.

AI may coach but cannot grade official evidence, reveal hidden tests, overwrite canonical truth or write mastery.
