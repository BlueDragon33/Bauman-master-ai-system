# MATH PROMPT ARCHITECTURE MAP
## From the earlier 10-prompt concept to the final 7-prompt constitution-routed system

The earlier planning concept separated Math into roughly ten subject prompts.

That was useful for discovering responsibilities, but it duplicated responsibilities already governed globally by the four shared constitutions.

The final active architecture is:

| Final owner | Responsibility | Earlier planning responsibilities absorbed |
|---|---|---|
| MATH00 | Orchestration / owner / constitution routing | overall coordination |
| MATH01 | Forensic audit/baseline | old M1 |
| MATH02 | Curriculum + knowledge graph + mathematical content constitution | old M2 + M3 |
| MATH03 | Problem solving + proof + assessment + mastery/adaptive specialization | old M4 + M5 Math-specific parts |
| MATH04 | Computation + visualization + simulation + AI Math Tutor | old M6 + M7 |
| MATH05 | Learner experience + authoring + product integration | old M8 + platform/UI integration |
| MATH06 | Math acceptance + hardening + legacy closure + RC readiness | old M9 + subject-specific part of M10 |
| Shared C3 release procedure | Exact-RC production deploy/verify/observe/rollback | generic production part of old M10 |

## What is deliberately global

These are not duplicated inside Math:

- platform kernel / Subject Factory / capability architecture;
- shared Design System / App Shell / responsive foundation;
- generic QA root-cause/auto-fix methodology;
- generic mastery/evidence philosophy;
- generic production release mechanics.

Math files only add the domain semantics needed for Mathematics.
