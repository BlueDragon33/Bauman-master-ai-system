# 7. FOUR-CONSTITUTION GATE

Every major Math feature must satisfy all relevant laws:

## C1 — Architecture

Can it be implemented as content, manifest, capability, adapter, extension or reusable block instead of a Math-specific platform fork?

## C2 — UI/UX

Does it use the shared design system, responsive rules, accessibility rules and interaction contracts?

## C3 — QA / Auto-Fix

Does it have reproducible tests, root-cause fix, regression and release evidence?

## C4 — Real Learning / Outcomes

Which competency does it build, what evidence does it produce, what weakness can it diagnose, and how does it support transfer?

Passing 3/4 is not completion.

# 10. DEFINITION OF PROMPT-SYSTEM SUCCESS

This architecture is correct only if:

- mathematical truth has a clear owner;
- learning evidence is not confused with clicks;
- reasoning is not reduced to final-answer string match;
- equivalent mathematical answers can be handled honestly;
- theorem/definition assumptions and domains are preserved;
- computation/visualization are reusable capabilities, not hidden truth owners;
- AI can coach but cannot silently redefine mathematics;
- Math UI uses the shared platform design system;
- normal content authoring does not require code surgery;
- Math-specific edge cases have regression coverage;
- production receives an exact accepted RC.
