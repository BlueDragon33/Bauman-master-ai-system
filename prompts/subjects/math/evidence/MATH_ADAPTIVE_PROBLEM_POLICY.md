# MATH03 · ADAPTIVE PROBLEM POLICY

Status: ACTIVE

Difficulty is a vector, not a scalar: algebraic complexity, step count, abstraction, representation switching, parameterization, proof depth, context novelty, computational burden, hint availability and time pressure.

## Adaptation rules
1. Trace target failure to prerequisite evidence before increasing difficulty.
2. Prefer a controlled variant over repeating the identical numeric instance.
3. Keep target competency/evidence dimension stable when generating a remediation variant.
4. Generated variants require solvability, domain validity, verified answer, non-degenerate constraints and a reproducible seed where useful.
5. Generated candidate content remains `GENERATED_CANDIDATE` until validation; it cannot rewrite MATH02 truth.
6. Hint usage changes evidence metadata, not automatic pass/fail.
7. Transfer tasks use a changed context while preserving the underlying target.

No mass problem generation is authorized by MATH03.
