# PDM06 — ACCEPTANCE · HARDENING · LEGACY CLOSURE · RC READINESS

Mode:

`PROJECT-STATE-REGRESSION · BASELINE-RED-TEAMED · STATUS-SKEPTICAL · NO-KNOWN-BLOCKER`

# MISSION

Prove Project Design Management is semantically correct, evidence-based, auditable, accessible and exact-RC ready.

# TEST MATRIX

## Objective / Scope
- vague objective;
- missing in/out scope;
- conflicting assumption;
- scope creep without change.

## Deliverables
- missing deliverable;
- duplicate deliverable;
- work activity mislabeled deliverable;
- acceptance criterion missing;
- rejected deliverable marked complete.

## Work / Dependencies
- unlinked work package;
- impossible dependency;
- circular dependency;
- hidden prerequisite;
- invalid milestone ordering.

## Responsibility
- unowned critical deliverable;
- conflicting authority;
- overloaded responsibility if resource scope exists.

## Plan / Baseline
- immutable baseline;
- unauthorized mutation;
- stale plan snapshot;
- invalid replan.

## Progress
- fake % complete;
- closed tasks but unaccepted deliverable;
- stale evidence;
- green status with unresolved blocker.

## Change
- scope/plan change without impact analysis;
- baseline revision missing;
- affected review/test/docs not updated.

## Risk / Issue
- risk without cause/event/consequence;
- issue treated as uncertain risk;
- closed risk without treatment/evidence.

## Review / Acceptance
- milestone/review closed with open blocking action;
- acceptance authority missing;
- handoff with incomplete deliverable.

## Schedule / Cost / Resource
Only if actual scope:
- estimate presented as certainty;
- unsupported cost;
- capacity conflict;
- schedule ignores dependency.

## Status Reporting
- report disagrees with source state;
- report lacks snapshot/revision;
- hidden blocker.

## AI
AI must not:
- fabricate completion;
- fabricate approval;
- fabricate dates/cost/effort;
- mark deliverable accepted;
- hide scope creep;
- write official mastery.

# AUTHORIZATION / AUDIT

Authoritative project-state mutation follows role/authority rules and leaves audit trail.

# ACCESSIBILITY

Dependency/timeline/status views have structured alternatives and non-color semantics.

# OFFLINE

Case learning verified where supported.
No conflicting offline authoritative project-state writes.

# LEGACY CLOSURE

Resolve duplicate:
- project registry;
- scope registry;
- deliverable registry;
- dependency engine;
- project timeline;
- change workflow;
- risk registry;
- decision log;
- status report provider;
- old routes/flags.

# FOUNDATION OWNER GATE

No duplicate LSE/OOPSE/HCI/Security/Reliability canonical truth.

# MIGRATION

If canonical IDs/schema change:
aliases,
project migration,
deliverable migration,
dependency/change/risk migration,
learner evidence preservation,
rollback.

# RC FREEZE

Freeze:
SHA,
content snapshot,
subject pack,
project-case revisions,
project-state schema,
provider config,
lockfile.

# PRODUCTION SMOKE PROFILE

1. open Project Design Management subject;
2. open one project/design case;
3. inspect scope and deliverables;
4. inspect work/dependencies/milestone;
5. inspect progress evidence;
6. run one change/risk/review scenario;
7. verify active project-case/subject-pack revision;
8. verify canonical state/provider profile;
9. verify optional AI grounded/fallback;
10. offline case if supported.

# BLOCKERS

- scope creep silently accepted;
- deliverable falsely marked accepted;
- project status fabricated or stale;
- baseline mutated in place;
- dependency logic invalid;
- AI fabricates approval/completion;
- unauthorized state mutation;
- duplicate canonical owner;
- migration corrupts learner evidence.
