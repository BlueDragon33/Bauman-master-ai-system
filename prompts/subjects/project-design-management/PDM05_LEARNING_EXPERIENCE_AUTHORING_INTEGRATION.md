# PDM05 — LEARNING EXPERIENCE · AUTHORING · PRODUCT INTEGRATION

Mode:

`SHARED-DESIGN-SYSTEM · DELIVERABLE-VISIBLE · NO-CODE-FIRST · ACCESSIBLE`

# ENTRY

Requires PDM02–PDM04.

# PRIMARY SURFACES

Possible:
- project/design charter;
- scope canvas;
- stakeholder map;
- deliverable tree;
- work-breakdown view;
- dependency graph;
- milestone/review timeline;
- responsibility matrix;
- progress/evidence board;
- change-impact workspace;
- risk register;
- decision log;
- status report;
- AI tutor;
- design-project portfolio.

# CHARTER UX

Show:
objective,
scope,
constraints,
stakeholders,
deliverables.

# SCOPE UX

In/out/assumptions/constraints visibly separated.

# DELIVERABLE TREE

Deliverables distinct from work activities.

# DEPENDENCY VIEW

Graph + accessible list/table.

# MILESTONE / REVIEW UX

Show evidence/exit criteria, not date alone.

# RESPONSIBILITY UX

Status not color-only.
Clear accountable owner.

# PROGRESS BOARD

Evidence states rather than fake percentages.

# CHANGE IMPACT UX

Highlight:
scope,
deliverables,
dependencies,
milestones,
risk,
technical links.

# RISK REGISTER UX

Cause-event-consequence + owner/treatment.

# DECISION LOG UX

Alternatives/rationale/evidence visible.

# STATUS REPORT UX

Generated from current canonical snapshot.
Timestamp visible.

# AI TUTOR UX

Advice visually distinct from approved plan/state.

# AUTHORING

No-code authoring can create:
- project context;
- scope case;
- deliverable/work-breakdown task;
- dependency task;
- responsibility case;
- change scenario;
- risk case;
- review/acceptance scenario;
- status-report critique.

# MULTIPLE VALID PLANS

Rubrics are criteria/evidence based, not exact Gantt matching.

# PREVIEW

`objective → scope → deliverables → plan → progress/change/risk → acceptance → grader`

# VALIDATION

Before review:
- IDs valid;
- dependencies valid;
- deliverables linked;
- hidden issues protected;
- invalid fixtures fail.

# SUBJECT MANIFEST

Register through Subject Factory.

# SUBJECT PACK

Canonical content + safe project cases + deliverable sets + plan/change/risk fixtures.

# OFFLINE

Case-based learning works offline where practical.
Shared authoritative writes require synchronized backend.

# ANALYTICS

Track:
scope revision,
plan decision,
dependency repair,
change analysis,
risk action,
review finding,
hint,
submission.

Do not treat number of completed tasks as mastery.
