# 5. NON-NEGOTIABLE INVARIANTS

- Requirements/behavior precede class diagrams.
- Class count is not a quality metric.
- Inheritance is not default reuse.
- Interfaces/contracts have semantic meaning.
- Coupling/cohesion are contextual, not slogans.
- Pattern names do not prove good design.
- Passing tests do not prove maintainability.
- Coverage does not prove correctness.
- Refactoring preserves intended externally observable behavior.
- AI-generated code remains subject to design/test/review rules.
- UML/view is not canonical truth by itself.
- Code is one implementation of a design, not always the design itself.
- Multiple valid designs may exist under the same requirements.
