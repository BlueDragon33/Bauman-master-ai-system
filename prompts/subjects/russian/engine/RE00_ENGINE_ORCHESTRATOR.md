# 0. MISSION

Build Russian Engine as an isolated implementation subsystem inside the existing Russian subject so the product can become materially stronger than translation-heavy language-learning apps in the dimensions that matter:

- direct semantic understanding;
- natural-speed listening;
- pronunciation and connected speech;
- response latency;
- contextual action;
- repair strategies;
- open-ended conversation;
- grammar intuition before grammar explanation;
- adaptive retention;
- transfer to real Russian life, university, technical and research contexts.

The Engine must remain:
- content-driven;
- testable;
- replaceable at internal boundaries;
- offline-capable where practical;
- provider-independent;
- multi-user ready;
- privacy-aware;
- commercially extensible;
- backward compatible with validated Russian learner state.

The goal is not to imitate a competitor's interface or proprietary content.

The goal is to create a superior learning architecture.

# 3. PEDAGOGICAL NORTH STAR

Primary acquisition path:

`SOUND → CONTEXT → ATTENTION → ACTION → CONSEQUENCE → MEANING → RESPONSE → RETENTION → TRANSFER`

Avoid defaulting to:

`RUSSIAN → TRANSLATION → RULE → ANSWER`

The learner should progressively reach:
- Russian sound evokes meaning directly;
- high-frequency chunks are processed as units;
- common grammatical patterns feel expected before formal naming;
- real speech remains understandable at natural speed;
- response starts without translating internally;
- repair strategies keep communication alive when comprehension is incomplete.

---

# 4. CHILD-LIKE DOES NOT MEAN MEANINGLESS

The Engine must never interpret “learn like a child” as random imitation without understanding.

A child receives rich grounding:
- visible objects;
- gaze;
- gesture;
- action;
- shared situation;
- consequence;
- repetition;
- emotional tone;
- predictable routines.

Therefore Engine immersion must maximize grounded meaning.

Preferred aids before translation:
1. replay;
2. visual focus;
3. gesture/animation;
4. object/action manipulation;
5. contrast;
6. scene consequence;
7. easier Russian;
8. known Russian paraphrase;
9. short explicit explanation;
10. native-language translation only when needed.

---

# 5. TRANSLATION POLICY

Default learner-facing translation mode:

`HIDDEN_BY_DEFAULT`

Translation may be:
- manually requested;
- enabled as accessibility/support;
- used temporarily after repeated failure;
- used for dangerous/high-stakes misunderstanding;
- used to explain abstract grammar when Russian-only explanation would exceed the learner's current comprehension.

Track translation dependency as learner-support telemetry.

Do not punish the learner for requesting help.

Do not let help become invisible permanent dependency.

---

# 6. NATURAL SPEECH POLICY

Train a progression from clear native speech to real connected speech.

Dimensions:
- rate;
- reduction;
- vowel reduction;
- devoicing/assimilation;
- phrase stress;
- intonation;
- linking;
- speaker variation;
- environmental noise;
- lexical predictability;
- interruption;
- ambiguity.

Slow playback is a scaffold.

It must not become the learner's permanent target.

---

# 7. 100-LEVEL CAPABILITY

The Engine must support at least 100 internal progression levels without hardcoding 100 separate pages.

Requirements:
- levels represented as data;
- each level references competencies and evidence gates;
- difficulty can vary on multiple axes;
- progression is not purely linear;
- review can pull earlier concepts;
- advanced learner may skip evidence-proven material;
- no level is granted merely for time spent or clicks;
- level number is presentation/progression metadata, not the only mastery truth.

The full ladder is defined by RE03.

# 10. NO MANDATORY NEW API

Do not create a standalone Russian backend/API merely because the Engine exists.

Prefer:
- concept graph;
- scene definitions;
- activity descriptors;
- difficulty dimensions;
- prompt variants;
- media refs;
- linguistic refs;
- evidence contracts;
- hint ladders;
- scenario graphs;
- assessment contracts.

Adding content should increasingly require data authoring, not feature coding.

# 13. AI ROLE

AI may:
- create ephemeral variants;
- act as conversation partner;
- coach;
- simplify Russian;
- generate non-canonical practice;
- explain;
- personalize support.

AI may not:
- silently alter canonical linguistic facts;
- directly grant mastery;
- invent world state that determines official success;
- silently store generated content as canonical;
- become required for core offline learning.
