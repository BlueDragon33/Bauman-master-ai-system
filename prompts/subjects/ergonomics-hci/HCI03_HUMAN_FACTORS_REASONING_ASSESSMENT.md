# HCI03 — HUMAN FACTORS REASONING & ASSESSMENT
Mode: `TASK-FIRST · EVIDENCE-AWARE · MULTIPLE-VALID-REDESIGN-AWARE`

# REASONING LOOP
`User → Goal → Task → Context → Information/control need → Interface behavior → Error/workload risk → Evidence → Root cause → Redesign → Re-evaluation`.

# ASSESSMENT DIMENSIONS
User/task model; context; information requirements; display/control; feedback/state visibility; human-error reasoning; accessibility; usability evidence; root cause; redesign; trade-offs; re-evaluation plan.

# REQUIRED CASES
Aesthetics vs usability; user error vs design-induced error; critical-task differences; information priority/label clarity; missing feedback; mode error; destructive action; memory burden; cognitive-load claim quality; color/typography/data display; dashboard density; alarm design if in scope; accessibility; usability study design; time-vs-error trade-off; heuristic vs observed-user evidence; human-AI uncertainty/override/automation bias.

# MULTIPLE VALID REDESIGNS
Grade criteria/evidence, not pixel match.

# ERROR TAXONOMY
`USER_TASK_MISMATCH`, `CONTEXT_OMISSION`, `INFORMATION_PRIORITY_ERROR`, `AMBIGUOUS_LABEL`, `STATE_VISIBILITY_ERROR`, `FEEDBACK_ERROR`, `MODE_ERROR`, `ERROR_RECOVERY_ERROR`, `COGNITIVE_LOAD_RISK`, `VISUAL_LEGIBILITY_ERROR`, `ACCESSIBILITY_ERROR`, `ALARM_DESIGN_ERROR`, `USABILITY_METHOD_ERROR`, `EVIDENCE_OVERCLAIM`, `AUTOMATION_BIAS_RISK`, `REDESIGN_ROOT_CAUSE_MISMATCH`.

# TEST-OF-TESTS
Reject “looks modern therefore usable”; automated accessibility score = fully accessible; fast completion despite serious errors = automatically better; one participant = universal proof; user blamed for unclear destructive control; AI recommendation accepted without required review/override.

# DELIVERABLES

# PASS
PASS when grader rejects aesthetic-only opinion, demands evidence and accepts multiple valid redesigns.
