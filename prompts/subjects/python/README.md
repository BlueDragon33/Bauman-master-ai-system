# 4. RUNTIME TRUTH HIERARCHY

The system must distinguish:

`LANGUAGE SEMANTICS`

from:

`SOURCE CODE`

from:

`RUNTIME EXECUTION`

from:

`TOOL OUTPUT`

from:

`PEDAGOGICAL EXPLANATION`

from:

`LEARNER EVIDENCE`.

A linter is not the Python language authority.

A formatter is not a correctness engine.

A notebook output is not necessarily reproducible evidence.

AI is not the authority for runtime truth, official score or mastery.

---

# 5. SUBJECT BOUNDARIES

Python owns Python language and Python-specific programming practice.

It may introduce interfaces to adjacent domains but must not absorb their canonical ownership.

Examples:

- Algorithms & Data Structures: separate subject owns algorithmic theory/complexity; Python may implement examples.
- Database/SQL: separate subject owns SQL/database semantics; Python may teach DB client patterns later.
- AI/ML: separate subject owns models/training theory; Python may provide tooling prerequisites.
- Linux/OS/Networks: separate subjects own those system concepts; Python may teach files/process/API usage only as Python integration.
- Mathematics: Math owns mathematical truth; Python may compute/visualize it.

# 8. FOUR-CONSTITUTION GATE

Every major Python feature must satisfy all relevant laws:

## C1 — Architecture

Can it be implemented through content, manifest, capability, adapter, extension or reusable block rather than a Python-specific platform fork?

## C2 — UI/UX

Does it use the shared Design System, App Shell, responsive rules, accessibility and interaction contracts?

## C3 — QA / Auto-Fix

Does it have reproducible tests, root-cause fixing, regression and release evidence?

## C4 — Real Learning / Outcomes

Which programming competency does it build, what evidence does it produce, which error class can it diagnose, and can the learner transfer the skill to a new program?

Passing 3/4 is not completion.

# 11. DEFINITION OF PROMPT-SYSTEM SUCCESS

This architecture is correct only if:

- Python language/runtime truth has a clear authority model;
- code reasoning is not reduced to final stdout string match;
- runtime errors and logic errors are distinguished;
- debugging is a first-class competency;
- assessment can evaluate behavior, reasoning, tests and transfer;
- notebook/REPL state does not masquerade as reproducible program state;
- execution is sandboxed and resource-limited;
- package/runtime versions are explicit where behavior differs;
- AI can coach/review/debug but cannot silently redefine runtime truth or mastery;
- Python UI uses the shared platform Design System;
- normal coding-task authoring does not require code surgery;
- Python-specific edge cases/security cases have regression coverage;
- production receives an exact accepted RC.
