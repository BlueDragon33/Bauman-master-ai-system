# PYTHON ERROR NOTEBOOK MAPPING

The global C4 Error Notebook remains the owner of learner error history. Python contributes stable error-pattern categories and remediation links; it does not create a second mastery/history store.

Examples:
- `mutation_aliasing` → `py.comp.state-mutation` → reference graph → trace tasks → transfer coding task.
- `off_by_one` → `py.comp.control-flow` / `py.comp.collections-iteration` → boundary table → regression test.
- `iterator_state` → `py.comp.iterators-generators` → lifecycle/exhaustion trace → fresh-context task.
- `import_environment` → `py.comp.modules-imports` / `py.comp.tooling-reproducibility` → isolate environment/import path → reproduce from declared state.
- `notebook_stale_state` → `py.comp.tooling-reproducibility` → restart/run-all → reproducible script/notebook check.
- `test_fixture` → `py.comp.testing-debugging` → inspect oracle/fixture → fix root cause → regression.

Record recurring patterns, not every typo forever. Remediation targets the underlying competency/error mechanism and then requires new evidence; “repeat the same question” is not sufficient remediation.
