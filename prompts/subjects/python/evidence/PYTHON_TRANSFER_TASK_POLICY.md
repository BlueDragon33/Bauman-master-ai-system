# PYTHON TRANSFER TASK POLICY

Transfer means applying the same underlying Python competency in a materially new context rather than replaying a memorized example.

A transfer task declares:
- source competency IDs;
- new domain/context;
- unfamiliar but fair inputs/cases;
- required artifact;
- explanation/demo requirement;
- allowed support;
- runtime/version scope;
- evidence acceptance criteria.

Difficulty may vary by scaffold amount, case count, data-structure complexity, program length, hidden-edge-case diversity, debugging ambiguity and requirement openness. Longer code is not automatically harder.

Preferred real outputs include a tested script, CLI utility, reusable module, file/data processor, small package, debug report, test suite or reproducible engineering/research utility. Adjacent Algorithms/Database/ML/Software-Engineering theory remains with its canonical owner.
