# PYTHON TRANSFER TASK POLICY

Transfer means applying the same underlying competency in a materially new context, not replaying a memorized sample.

A transfer task should vary at least two of:
- domain/context;
- data shape;
- edge-case distribution;
- scaffold amount;
- program structure;
- requirement openness;
- debugging ambiguity.

Keep the canonical competency stable while context changes.

Credible outputs may include a tested script/module, data transformation, CLI utility, debugging report, test suite or small research/engineering utility.

Scaffolding should reduce over time. A task may begin with starter code, but evidence metadata must distinguish scaffolded from independent construction.

Adjacent-domain transfer may use Algorithms/Database/ML/Software Engineering contexts without redefining those subjects' theory.
