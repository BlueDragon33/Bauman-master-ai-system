# NIRVKR05 — RESEARCH WORKSPACE · AUTHORING · PRODUCT INTEGRATION

Mode:

`ONE-PROJECT-WORKSPACE · TRACEABILITY-VISIBLE · NO-CODE-FIRST · ACCESSIBLE`

# ENTRY

Requires NIRVKR02–NIRVKR04.

# PRIMARY SURFACES

Possible:
- research-project dashboard;
- topic/objective history;
- stage/milestone timeline;
- supervisor context;
- artifact registry;
- literature/evidence matrix;
- experiment/run registry;
- code/data/model provenance;
- result/claim/limitation workspace;
- feedback/revision matrix;
- NIR/practice/pre-diploma deliverable views;
- manuscript coverage view;
- reproducibility checklist;
- defense package;
- final archive;
- AI tutor.

# PROJECT DASHBOARD

Show:
current topic revision,
active stage,
next gate,
blocking issues,
artifact health,
readiness evidence.

# TOPIC HISTORY

Never overwrite approved/previous topic revisions.

# MILESTONE TIMELINE

Show stage boundaries and evidence, not generic project progress only.

# ARTIFACT REGISTRY UX

Filter by:
stage,
type,
status,
revision,
owner,
staleness.

# EVIDENCE MATRIX

Question/objective/task → evidence/result/artifact.

# EXPERIMENT UX

Reference technical-subject/RSW run records.

# PROVENANCE UX

Clickable chain:
claim → result → run/source → data/code/model.

# FEEDBACK / REVISION UX

Feedback item → required action → changed artifact → resolution evidence.

# MANUSCRIPT COVERAGE

Show actual template sections only after institutional evidence.

# REPRODUCIBILITY UX

Checklist plus evidence links.

# DEFENSE UX

Presentation claim → manuscript/result source.
Demo → exact runtime/code/model/data revision.

# FINAL ARCHIVE UX

Manifest-first:
what artifact,
which revision,
hash/identity,
purpose.

# AI TUTOR UX

Advisory.
Never displays AI suggestion as supervisor approval.

# RESPONSIVE / ACCESSIBILITY

Trace graphs have structured alternatives.
Readiness status not color-only.
Keyboard and large text supported.

# AUTHORING

Authorized instructor/admin can configure:
- stage templates;
- artifact requirements;
- readiness criteria;
- feedback categories;
- manuscript template;
- defense package template.

Institution-specific authoring requires evidence/source reference.

# NO-CODE RULE

Ordinary stage/template updates should not require app-code changes.

# SUBJECT INTEGRATION

Reference artifacts from prior subjects instead of copying them.
